# 과거 공고는 기존 스냅샷과 수동 공개 사례로 제공

상태: 채택 · 2026-10-15

## 결정

현재 공고와 분리된 `/history`를 정적 출력한다. DB 테이블은 추가하지 않고 기존 `JobSnapshot`의 접수 중 원문을 수집 시점으로 재분류한다. 기준에 맞았던 가장 최근 원문을 우선하며, 없으면 마지막 접수 중 원문 또는 미확인 자료를 보관한다.

화면 데이터에는 `history` 배열과 각 기록의 `historical` 메타데이터(근거 종류·평가 시점·모집 연도·주의사항)를 추가한다. 현재 공고 배열의 의미와 기존 네 테이블은 유지한다. 스냅샷이 없으면 날짜를 역산하지 않는다. 원문이 살아 있는 과거 공개 사례는 `config/history.ts`에 출처·요약·불확실성을 관리한다.

## 결과와 한계

새 크롤러·DB 마이그레이션 없이 기존 수집 상태 백업·복원·Pages 빌드를 사용한다. 과거 공고 전체를 복구하지는 못한다. 과거 화면은 현재 규칙을 과거 본문에 적용하는 참고 자료이며 당시 법규, 개인 자격, 합격 가능성을 판정하지 않는다. 현재 지원 가능 상태와 혼동하지 않도록 화면에서 분리하고 `USER_ELIGIBILITY=unknown`을 유지한다.
